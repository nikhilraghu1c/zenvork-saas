# Render deployment

The repository includes `render.yaml` for a no-domain test deployment:

- `zenvork` is a Node web service in Singapore.
- Its Express process serves the built Angular application and the `/api` routes from one temporary
  `onrender.com` URL; no custom domain is required.

Create the Blueprint from the repository in Render. Render prompts for `MONGO_URI`; use the Atlas
connection string and add Render's outbound access in Atlas if network restrictions are enabled.
`ACCESS_TKN_SECRET` is generated by Render. Do not place it, the MongoDB URI, or any production
secret in Git.

The build command uses `npm ci --include=dev` because Angular CLI is a build-time dev dependency,
even though the running service uses `NODE_ENV=production`.

The Angular build receives an empty `API_URL` and writes that to the deployed `runtime-config.js`.
The browser consequently calls the same-origin `/api` routes. The API receives its own public URL
as `CLIENT_ORIGIN`. This makes URLs environment-specific without changing source files.

Serving frontend and API from one origin keeps the default `SameSite=Strict` HttpOnly session cookie
reliable. A separate static site and API with temporary `onrender.com` URLs would make that cookie
cross-site and is intentionally avoided.

Express serves `index.html` for non-API paths so Angular routes work after a direct refresh.
